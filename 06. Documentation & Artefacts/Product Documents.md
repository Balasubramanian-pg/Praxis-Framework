# Product Documents

> [!SUMMARY] Overview
> A collection of granular specifications, descriptions, and quality criteria for individual products and components.

## Purpose
**Product Documents** assemble detailed technical specifications, quality criteria, interface contracts, and maintenance metadata for individual deliverables within the project scope. 

In enterprise IT data projects, deliverables are governed under the **"Data as a Product"** paradigm. Each data product (whether an ingestion pipeline, a transformed dimensional mart, a semantic metric layer, or an executive dashboard) requires formal product documentation to ensure architectural alignment, backwards compatibility, and self-service discoverability.

```
                     Enterprise Data Product Architecture
                     
[Upstream Source] ──► [1. Producer-Consumer Data Contract]

[Silver/Gold Layer] ─► [2. dbt Transformation & Metric Specification]
                             │
                             ▼
[Semantic Layer] ────► [3. BI Dashboard Design Brief & Wireframe Spec]
                             │
                             ▼
[Production CI/CD] ──► [4. Automated Quality Register & Observability]
```

### 1. The Producer-Consumer Data Contract (`contract.yaml`)
A binding technical agreement between source application owners (e.g., Salesforce, SAP, Core Banking) and the downstream Data Platform team. It specifies schema expectations, delivery SLAs, and breaking-change governance.

```yaml
# Data Product Specification: Customer Orders Stream
version: 2.1.0
domain: Sales & Billing
dataset: raw_orders_stream
owner: billing-eng@internal.corp
sla:
  freshness_latency: 15m
  availability: 99.9%
schema:
  - column: order_id
    type: string
    description: "UUID primary key generated by billing gateway"
    constraints: [unique, not_null]
  - column: customer_id
    type: string
    description: "Foreign key referencing dim_customers"
    constraints: [not_null]
  - column: total_amount_usd
    type: decimal(18,2)
    description: "Net transactional amount in USD"
    constraints: [min_value: 0.00]
  - column: order_timestamp
    type: timestamp_tz
    description: "UTC event time of payment settlement"
    constraints: [not_null]
breaking_change_policy:
  notification_lead_time_days: 30
  deprecation_support_months: 3
```

### 2. dbt Model & Semantic Layer Specification (`schema.yml`)
The formal definition of conformed Silver/Gold dimensional models, primary keys, referential integrity tests, and certified enterprise business metrics.

```yaml
# Gold Dimensional Model: Fact Daily Sales Performance
version: 2
models:
  - name: fct_daily_sales
    description: "Curated Gold fact table capturing daily settled order volume at store-SKU grain."
    config:
      materialized: incremental
      unique_key: [date_key, store_id, product_id]
      cluster_by: [date_key, store_id]
    columns:
      - name: date_key
        description: "Surrogate key referencing dim_date (YYYYMMDD)"
        tests:
          - not_null
          - relationships:
              to: ref('dim_date')
              field: date_key
      - name: gross_revenue_usd
        description: "Gross total billed prior to returns and discounts"
        tests:
          - not_null

semantic_models:
  - name: sales_metrics
    model: ref('fct_daily_sales')
    entities:
      - name: store
        type: foreign
        key: store_id
    measures:
      - name: total_gross_revenue
        agg: sum
        expr: gross_revenue_usd
    dimensions:
      - name: order_date
        type: time
        expr: date_key
        type_params:
          time_granularity: day
```

### 3. Executive BI Dashboard Design Brief (`dashboard_brief.md`)
The functional design brief for visualization developers and business change managers, ensuring reports are built against user personas, actionable decisions, and strict performance SLAs.

| Specification Field | Requirement Details |
| :--- | :--- |
| **Product Name** | Global Executive Revenue & Margin Cockpit |
| **Target Persona** | Chief Financial Officer, VP of Global Sales Operations |
| **Key Business Decision** | Determine whether regional discounting is eroding net margin below target thresholds. |
| **Refresh Frequency** | Daily at 06:00 UTC (automated via Power BI Service Scheduled Refresh). |
| **Performance Budget** | Initial dashboard load < 2.0s; visual cross-filter slice response < 800ms. |
| **Row-Level Security (RLS)** | Regional Sales Directors restricted to their assigned territory (LDAP security group sync). |
| **Visual Hierarchy** | Top 4 Cards: Net ARR, Gross Margin %, Churn Rate, Expansion ARR.<br>Mid Section: Waterfall chart of ARR movements.<br>Bottom Table: Store-level drill-through down to invoice line items. |

## Data Product "Definition of Done" (DoD) Checklist

A Data Product is considered delivered only when the following criteria in the Product Documents are certified:

- [ ] Data Contract signed by upstream producer and consumer teams.
- [ ] dbt transformation models versioned in Git with 100% passing tests (`not_null`, `unique`, `relationships`).
- [ ] Catalog metadata, column descriptions, and lineage published to Unity Catalog / Purview.
- [ ] Semantic layer metrics reconciled with the General Ledger / Source of Truth.
- [ ] BI Dashboard audited for mobile responsiveness, RLS enforcement, and sub-2-second render performance.
- [ ] Deprecation schedule for legacy Excel reports agreed with Business Change Managers.
